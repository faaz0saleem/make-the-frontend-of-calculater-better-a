# Wobble Haul

A colourful 3D arcade delivery runner. You drive a tiny truck carrying a comically tall stack of boxes, cakes, fridges and pianos through a sunny harbour, a windy canyon and a neon night market. The truck drives forward on its own. You steer, pick up cargo, keep the stack balanced, shed the top item when you have to, and deliver it. More cargo pays more, but it also makes the truck harder to handle.

- **Delivery Tour:** 30 authored levels across 3 worlds, each with 3 optional medals.
- **Long Haul:** an endless road. Bank cargo at depots, or carry it on for a bigger multiplier.
- **Daily Contract:** the same route, truck and conditions for everyone on a given UTC day, with a once-per-day bonus.
- **Garage:** 5 trucks, 14 paints, 7 extras, 3 upgrade tracks with 5 tiers each, and Spare Tires. Everything is bought with earned coins only.

Built with TypeScript, Vite and three.js, plus a plain HTML/CSS UI and procedural WebAudio. Every model, texture and sound is generated by the code; see `ASSET_LICENSES.md`.

## Requirements
- Node.js 22+ and npm 10+
- For browser tests: Chromium via Playwright 1.56.1. On machines without the bundled browser, run `npx playwright install chromium`. In this repository's CI container, Chromium is preinstalled.

## Setup & run
```bash
npm ci                # install exact locked versions
npm run dev           # dev server on http://localhost:5173 (dev tools enabled)
```
Useful dev URL parameters (dev server only):
- `?platform=dev`: simulated platform. Add `&ads=finish|unfilled|adblock|adCooldown|late|duplicate|never`, `&muteAudio=true`, or `&profile=<name>` for a separate save.
- `?dev=1`: performance/debug overlay. The backquote key `` ` `` toggles it.
- `?platform=standalone`: skip the CrazyGames SDK and save to localStorage.

## Build
```bash
npm run build         # Basic Launch build (default): no ad UI anywhere  -> dist/
npm run build:full    # Full Launch code paths enabled (ads wiring)       -> dist/
npm run budget        # size/file-count checks vs CrazyGames limits       -> qa/budget.json
npm run package       # upload ZIP with index.html at the root            -> release/wobble-haul-basic.zip
npm run release       # typecheck + unit tests + build + budget + package
```
For a Full Launch package run `npm run build:full && node scripts/package.mjs dist full`.

### Release stages (explicit)
| | Basic Launch (default) | Full Launch |
|---|---|---|
| Build command | `npm run build` | `npm run build:full` |
| CrazyGames SDK v3 | Integrated (loading/gameplay events, mute setting, Data module saves) | Same |
| Ads | None. No ad buttons or placeholders, and the SDK ad API is never called | Optional rewarded Spare Tire offer on the crash screen (occasional), optional rewarded paint trial in the Garage, midgame ads only at results-screen round boundaries |
| Approval | Upload via the developer portal | **Requires CrazyGames selection, integration and review.** Building with `--mode full` does not grant Full Launch. |

Production builds strip all development tools (dev overlay, simulated platform). Query-gated QA hooks (`?qa=1`) remain so automated tests can drive the production build. They only read state, toggle the scripted test driver, and change simulation speed; they never grant rewards.

## Tests
```bash
npm run typecheck     # tsc --noEmit
npm test              # 76 unit tests (Vitest)
npm run build && npm run e2e   # Playwright against the production build in a nested-path iframe
npx playwright test tests/e2e/screens.spec.ts   # screenshot matrix (12 sizes) + layout audit -> qa/
```
Tuning harnesses (not part of CI) live in `tests/tools`. Run them with `npx vitest run -c vitest.tools.config.ts <name>`, for example `leveldoc` (regenerates LEVEL_DESIGN.md), `economy`, `diag`, `explore`.

## Deploying to CrazyGames
1. `npm run release` (or `npm run build:full` plus packaging for an approved Full Launch).
2. Upload `release/wobble-haul-basic.zip` in the developer portal as an HTML5 game. `index.html` sits at the ZIP root and all asset paths are relative.
3. In the submission form, **enable the Progress Save (Data module) option**. Without it the Data module is disabled and progress will not persist.
4. Orientation: landscape and portrait both work. Declare the supported orientations in the submission form; the game does not lock orientation.
5. Use the portal's preview/QA tool to verify: the SDK environment is `crazygames`, gameplay events fire, saves round-trip for a guest and for a signed-in account, and the mute setting works.
6. Submission copy, tags and controls text are in `SUBMISSION.md`. Covers and preview videos are in `media/` (see `media/README.md`).

Self-hosting elsewhere: serve `dist/` from any static host. When the SDK reports the `disabled` environment (not on a CrazyGames domain), the game falls back to a namespaced localStorage save.

## Project layout
```
src/core        loop, rng, pause reasons, state machine, time
src/data        all tunable content: cargo, trucks, cosmetics, upgrades, economy, chunks, levels
src/sim         track-space road, truck + cargo stack, run session, builder, autopilot (tests/media)
src/modes       campaign builder & medals, endless generator, reachability validator, daily contract
src/render      three.js renderer, materials, procedural models, world chunks, sky, effects, garage stage
src/game        game orchestrator, run view, gameplay lifecycle gate
src/ui          DOM screens, HUD, garage, icons, styles
src/audio       procedural WebAudio
src/progression save schema/migrations, storage adapters, transactions, rewards
src/platform    PlatformAdapter (CrazyGames SDK v3 / standalone / dev), ad controller
tests/unit      Vitest suites; tests/e2e Playwright; tests/tools tuning harnesses
scripts         budget, packaging, nested-iframe server, capture helpers
```
