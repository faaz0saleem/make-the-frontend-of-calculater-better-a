# DECISIONS

Design and engineering decisions, with reasons. Newest last.

1. **Title: "Wobble Haul".** The working title "OVERLOADED!" is close to *Overload* (Revival Productions, 2018) and is a generic word used by many small games. Web searches on 10 Oct 2026 found no game called "Wobble Haul" (also checked "Teeter Truck", "Tall Order Express", "Stacked Delivery"). This is not a trademark clearance; the owner should run one before launch.
2. **Stack: TypeScript + Vite + three.js, no UI framework.** DOM overlay for UI, no framework in the per-frame loop. No physics library: the stack is a custom fixed-step model, cheaper and more controllable than rigid bodies.
3. **Track-space simulation.** Everything simulates in (s = distance along road, x = lateral). World-space is only for rendering. This makes collisions, lane logic, generation and validation simple and deterministic.
4. **Cargo stack model: independent damped oscillators per interface.** A fully coupled chain produced whiplash where mid-stack items failed first, which read as random. With per-interface oscillators driven by the inertial acceleration at the item's height (lever arm), plus load-dependent stiffness, the top item is reliably the most exposed. That matches the "shed the top item" mechanic. Mass matters through stiffness (heavy loads above stiffen lower interfaces), crush limits, gust sensitivity (area/mass) and rollover (combined COM height).
5. **Rollover uses combined centre of mass.** Raw cargo mass made heavy appliances tip a pickup on any corner. Using the ballast+cargo COM height keeps rollover tied to how tall the load is, with wheel-lift warning at 72% and a 0.45 s grace before tipping.
6. **Arcade steering.** Steering sets a target lateral velocity with an acceleration limit. Corners add only a small outward drift (11% of v²κ); the cargo feels scaled corner/steer accelerations through a 0.1 s low-pass ("suspension compliance").
7. **Medians deflect instead of stopping.** Long walls have a wedge nose that pushes the truck aside (scrape + wobble). Head-on crashes only come from short barriers, carts and moving gates, never from route splits.
8. **Forks are lateral, not branches.** A fork widens the road and adds a median; each side is a "route". This keeps track-space linear while still offering real route choices (risky/safe, cliff jump, rooftop).
9. **Reachability guarantee.** `modes/reach.ts` runs a DP over a 1 m × 0.25 m grid with lateral spread limited by the slowest-steering effective lateral speed at the highest speed, ramp flights for both min and max speed, and landing-zone checks. Endless candidates that fail are rolled back and replaced; a breather chunk is the fallback.
10. **Load clearance guarantee in endless** covers stacks up to 4.8 m above the road at generation time. Taller stacks may need shedding; that is the intended decision.
11. **Campaign completion = reaching the depot.** Medals (delivery value, route objective, care objective) are optional. Worlds unlock by finishing level 10 of the previous world.
12. **Recovery token ("Spare Tire").** Bought with coins (140, max 3) or, in Full Launch builds only, granted by an occasional opt-in rewarded ad. One per run. Never in the Daily Contract. Cargo already lost stays lost.
13. **Daily claim is monotonic.** A daily bonus can only be claimed for a UTC date key later than the last claimed one. Reloads, repeated result screens and moving the clock back cannot pay twice. Moving the clock forward can claim a future date early, but then the skipped real dates cannot be claimed, so it never produces more claims than days advanced. Client-only, not anti-cheat.
14. **Save authority.** On CrazyGames the Data module is the only progress store (guests and accounts). If the first read fails, the game runs in memory and never writes, so it cannot overwrite an account save with defaults. If the SDK fails to load on a CrazyGames host, progress is memory-only (no competing localStorage database). Off-platform (SDK environment `disabled`) a namespaced localStorage key is used.
15. **SDK script is injected dynamically** (with a 9 s timeout) rather than a static `<script>` tag, so a blocked SDK never blank-screens the game. `SDK.init()` is awaited before any module use.
16. **No emojis/brand assets/fonts beyond Fredoka (OFL).** All art is procedural geometry; all audio is synthesised at runtime.
17. **Midgame ads**: Full Launch only, only on "Retry"/"Next" after a results screen, never before 3 minutes into a session, never in the same break as a rewarded offer, at most once per 3 minutes client-side (the SDK enforces its own limits too). Basic builds contain no ad UI.
18. **Media is rendered by the game itself.** `scripts/capture.mjs` runs a capture build (`vite build --mode capture`: dev tools on, plus capture hooks and `preserveDrawingBuffer`; it is never shipped) and steps the game's own clock by exactly 1/30 s per video frame, so playback runs at real game speed. Covers are staged in-engine compositions: the real renderer and models, with the cargo tower, camera and the title text placed by the script, the HUD hidden and loose coins near the camera removed. Preview videos are unedited scripted-driver gameplay (the same `Autopilot` the tests use) through the normal follow camera, with the HUD hidden, hard cuts between three clips and no audio track.
19. **Performance numbers are labelled by environment.** The only browser available here is headless Chromium on SwiftShader (software GL). FPS measured there says nothing about player hardware, so QA_REPORT.md reports it as a software-renderer number and relies on draw calls, triangles and resource counters, which do not depend on the GPU.
20. **The tutorial is shorter than the 60–90 s rule.** Harbor 1 is about 36 s so a first-time player reaches a delivery and the menus quickly after their one gesture. Levels 2–30 run 61–82 s at their average speed, and `levels.test.ts` enforces 60–90 s for every non-tutorial level.
